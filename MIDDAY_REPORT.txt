4. PHASE 2 -- THE BUILD (commit be30a18, 18 steps, all compiled along the way)
--------------------------------------------------------------------------------
STACK: React 19.2 + TypeScript ~6 (strict) + TanStack Query 5.104 +
       Vite 8.3 + oxlint + vanilla CSS with design tokens. 100% frontend,
       in-memory mock service (25 emails), no backend.

DATA & SERVICE
  - 25 seed emails across INBOX/SENT/DRAFT/SPAM/TRASH, unread counts,
    labels, attachments, snoozed entries
  - Total service operations: every guard is a silent return, nothing throws
  - Drafts materialize on first autosave; send transitions the SAME id
    DRAFT -> SENT (never delete + recreate)
  - Delete routed by the email's OWN container (TRASH|SPAM|DRAFT ->
    permanent, else -> Trash with restoreTo recorded)

QUERY LAYER
  - Single ['emails'] query key; all views, badges, and selection targets
    derive from one cached array
  - 15 mutation hooks; container-keyed derivations (selectForView,
    selectUnreadCount) that never move a badge during search

UI
  - Layout: sticky TopBar (debounced 200ms search), Sidebar with 9 Views
    + label pseudo-views + unread badges (Inbox/labels only), main area
  - EmailList / EmailRow / EmailToolbar / EmailView / ComposeWindow
  - Compose: 2s debounced autosave, "Draft saved" on close, inline
    zero-recipient error, Cc/Bcc toggle, reply/forward prefills,
    discard button, mobile bottom-sheet
  - Snooze derived from snoozedUntil (snoozed rows leave Inbox, return
    automatically when the timestamp passes)
  - Selection + bulk toolbar acting on selected INTERSECT visible only
  - Toasts for every completed action
  - Keyboard: c  /  j  k  Escape  e  #  s  u, plus Enter and Space on rows
  - Design system: ~850 lines of tokenised CSS (--c-*, --dur, --ease),
    prefers-reduced-motion honoured, responsive at 768px
  - Accessibility: aria-labels everywhere, aria-pressed on toggles,
    role=button rows, focus handling

VERIFICATION (during the build)
  - 3 Playwright suites, ~35 assertions: filtering, search scope,
    badge stability, archive/delete/restore routing, snooze, star,
    reply prefill, autosave, keyboard, labels -- zero console errors

6. PHASE 4 -- THE FIXES (commits 8a3c6a5, 6db877b)
--------------------------------------------------------------------------------
BUGS AND SPEC GAPS
  [x] Draft rows (click AND Enter) now open ComposeWindow pre-filled with
      draftId / recipients / subject / body; sending moves the same id
      DRAFT -> SENT and the row leaves Drafts
  [x] EmailView reached via j/k shows "Edit draft" instead of Reply --
      reply-on-draft would fabricate a second message
  [x] saveDraft persists to/cc/bcc so a re-edited draft keeps its To field
  [x] Compose window keyed by a per-open composeToken: pressing c or
      Reply while compose is open remounts fresh state (stale draftId
      could previously save content into the wrong draft)
  [x] Replaced compose saves its content on unmount (spec 0.6)
  [x] Discard button actually discards: clears the autosave timer,
      deletes the materialized row, closes with no save and no toast
      (it used to reuse the close handler -- saving and toasting)
  [x] Responsive bug (guardrail #9): .row__meta was not hidden at <=768px,
      so 4 grid children fought over 3 tracks and squashed the subject;
      now exactly [checkbox / sender / subject] = 40px 120px 1fr
  [x] Incomplete isPending gating: snooze/unsnooze/restore/spam menu items
      were never disabled; every aggregate pending now covers the
      mutation it gates, in row, view, and toolbar
  [x] Space now activates rows alongside Enter
  [x] QueryClient gained gcTime: Infinity and retry: false (spec 1 block
      was incomplete)
  [x] Topbar toolbar select-all: checkbox now selects all visible, then
      flips to Clear selection (was hardwired to Clear only)
